# Deploying the dev site

| Part | Where | Plan | Address |
| --- | --- | --- | --- |
| Web (Next.js) | Vercel, project root `web/` | Hobby (free) | `https://gully11-dev.vercel.app` |
| API (FastAPI) | Render, from `render.yaml` | Free | `https://gully11-api-dev.onrender.com` |
| Database | Neon | Free (0.5 GB; ours is ~135 MB) | private connection string |

All in Singapore, the closest free regions to India. Later, `dev.gully11.com`
becomes a CNAME to Vercel and `api.dev.gully11.com` one to Render.

**Free-plan behaviour:** the API sleeps after 15 idle minutes. The next visit wakes
it (about a minute; pages wait up to 60 s), and a live auction room is lost if
everyone in it goes idle long enough for that to happen.

## One-time setup

1. **Neon** (sign in with GitHub): create project `gully11-dev`, region Singapore,
   Postgres 16. Copy the connection string (with `?sslmode=require`).
2. **Load the data** from your machine (local Postgres running):
   ```powershell
   .\api\scripts\copy_db.ps1 -Target "<neon connection string>"
   ```
   Copies players, stats, venues and legends; the app's own tables arrive empty.
3. **Render** (sign in with GitHub): New → Blueprint → `sha728/gully11`. It reads
   `render.yaml`, generates `XI_SECRET`, and asks for `DATABASE_URL`: paste the Neon
   string. When it's live, `https://<service>.onrender.com/api/v1/health` returns
   `{"status":"ok"}`.
4. **Vercel** (signed in with GitHub): Add New → Project → `sha728/gully11`, Root
   Directory `web`, project name `gully11-dev`, environment variable
   `NEXT_PUBLIC_API_URL` = `https://<service>.onrender.com/api/v1`. Deploy.

After that, every merge to `main` redeploys both.

## Settings the API reads

| Variable | Dev site | Notes |
| --- | --- | --- |
| `DATABASE_URL` | Neon string | |
| `XI_SECRET` | generated by Render | the API refuses to start without one when `ENVIRONMENT` isn't `local` |
| `ENVIRONMENT` | `dev` | |
| `CORS_ORIGIN_REGEX` | Gully11's `*.vercel.app` addresses (+ localhost) | add the custom domain when there is one |

## Updating the data

Run the pipeline locally, then `copy_db.ps1` again. It replaces the stats tables
and empties the app's tables (drafts, challenges, auctions, seasons) on the target.
